Вариант 3: журналирование записи посетителя на тренировку.
SLF4J 2.0.17 и Logback 1.5.18 уже были в pom.xml; добавлены Logger и конфигурация вывода.
Java 17, Maven Checkstyle Plugin 3.6.0, Checkstyle 10.21.4.

FitnessService формирует:
- INFO: посетитель успешно записан; в сообщении идентификаторы клиента и тренировки.
- WARN: свободных мест нет либо клиент уже записан. Метод возвращает false.
- ERROR: тренировка отсутствует или хранилище выбросило исключение. Записывается стек ошибки,
  исходное исключение передаётся вызывающему коду. Бизнес-логика отказа сохранена.

Main использует Logger вместо System.out.println. Вывод настроен в консоль и
logs/fitness-center.log, файлы ротируются ежедневно и хранятся семь дней.
Логи и target исключены из Git.

## Правила Checkstyle

Проверяются основные исходники и тесты.
- LineLength: длина строки не более 100 символов.
- TypeName: имена типов соответствуют соглашению UpperCamelCase.
- MethodName: имена методов соответствуют lowerCamelCase.
- LocalVariableName: имена локальных переменных соответствуют lowerCamelCase.

Цель checkstyle:check возвращает ненулевой код при нарушениях. Она также привязана к verify.
В Jenkins проверка выделена в отдельный этап после Build и перед Test.

## Ответы на контрольные вопросы

1. Static Analysis — проверка исходного кода без запуска приложения.
2. Тестирование исполняет код и проверяет поведение; статический анализ проверяет его структуру.
3. Checkstyle — инструмент проверки Java-кода по правилам оформления.
4. Code Style — соглашения об именах, форматировании и организации кода.
5. Нарушение — несоответствие исходного кода настроенному правилу.
6. Да, приложение запускать не требуется.
7. Checkstyle сообщает файл, строку и правило; check завершается ошибкой при нарушениях.
8. Logging — запись событий выполнения программы.
9. println не предоставляет систему уровней, маршрутизации и централизованной настройки.
10. Logger — объект, через который класс отправляет сообщения в систему журналирования.
11. Log Level — важность события.
12. INFO — штатное событие, например успешная запись на тренировку.
13. WARN — ожидаемый проблемный исход, например отсутствие свободных мест.
14. ERROR — ошибка выполнения, например сбой хранилища или неизвестная тренировка.
15. SLF4J — фасад, через который приложение обращается к реализации Logging.
16. Logback — реализация журналирования.
17. Бизнес-код вызывает SLF4J, Logback обрабатывает и выводит сообщения.
18. После Build, до Test.
19. При ненулевом коде Maven этап завершается ошибкой; следующие обычные этапы пропускаются.
20. Анализ выдаёт нарушения исходников, Logging — события реального выполнения.
21. В CI анализ автоматически проверяет каждое изменение по одинаковым правилам.
